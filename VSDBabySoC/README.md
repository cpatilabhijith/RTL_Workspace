# VSDBabySoC — RTL Simulation, Synthesis and Gate-Level Verification

## Overview

VSDBabySoC is a small System-on-Chip that brings together a RISC-V processor core, PLL, and DAC in a single design. This project demonstrates how the design progresses from RTL implementation to a synthesized gate-level circuit and how its functionality can be verified after synthesis.

The work includes RTL simulation, synthesis using Yosys, mapping to the Sky130 standard-cell library, generation of the synthesized netlist, netlist visualization, and post-synthesis functional simulation.

# 2. VSDBabySoC Architecture

The VSDBabySoC design is built by connecting multiple hardware blocks through the `vsdbabysoc` top-level module.

The major components are the RVMYTH processor, PLL, and DAC.

```text
                    VSDBabySoC
                        |
          +-------------+-------------+
          |             |             |
        RVMYTH         PLL           DAC
          |             |             |
     RISC-V Core     Clock Source    Output
```

### RVMYTH

RVMYTH is the RISC-V based processor core used as the main digital processing unit of the SoC.

### PLL

The Phase Locked Loop (PLL) provides the clock-related functionality required by the system.

### DAC

The Digital-to-Analog Converter (DAC) receives the digital data generated by the processor section and provides the output signal.

### `vsdbabysoc`

The `vsdbabysoc` module is the top-level module. It connects the individual blocks and defines how they interact with each other.

# 4. Pre-Synthesis Simulation

Before converting the RTL into standard cells, its functional behavior is checked through simulation.

The RTL simulation follows this sequence:

```text
RTL Source
    +
Testbench
    |
    v
Compilation
    |
    v
Simulation
    |
    v
VCD File
    |
    v
GTKWave
```

Icarus Verilog is used to compile the RTL and testbench:

```bash
iverilog -o ./pre_synth_sim.out -DPRE_SYNTH_SIM src/module/testbench.v -I src/include/ -I src/module/
```

The compiled simulation is executed with:

```bash
./pre_synth_sim.out
```

The generated waveform file can be opened in GTKWave:

```bash
gtkwave pre_synth_sim.vcd
```

The waveform is used to observe signals such as:

* `CLK`
* `reset`
* `OUT`
* `RV_TO_DAC[9:0]`

# 5. Yosys Synthesis

Once the RTL behavior has been checked, the design is passed to Yosys for logic synthesis.

Synthesis transforms the RTL description into a lower-level logic representation that can be implemented using cells from the selected technology library.

The basic process is:

```text
RTL
 ↓
Synthesis
 ↓
Optimization
 ↓
Technology Mapping
 ↓
Gate-Level Netlist
```

## Reading RTL Files

The top-level RTL file is loaded first:

```tcl
read_verilog src/module/vsdbabysoc.v
```

The RVMYTH source is then included:

```tcl
read_verilog -I src/include/ src/module/rvmyth.v
```

The clock-gating module is also read:

```tcl
read_verilog -I src/include/ src/module/clk_gate.v
```

The include option allows Yosys to locate additional files required by the RTL.

## Reading Liberty Files

The PLL library is loaded using:

```tcl
read_liberty -lib src/lib/avsdpll.lib
```

The DAC library is loaded using:

```tcl
read_liberty -lib src/lib/avsddac.lib
```

The Sky130 standard-cell library is added with:

```tcl
read_liberty -lib src/lib/sky130_fd_sc_hd__tt_025C_1v80.lib
```

## Selecting the Top Module

The synthesis process is initiated with:

```tcl
synth -top vsdbabysoc
```

Here, `vsdbabysoc` is specified as the top module of the design hierarchy.

# 6. Technology Library and Cell Mapping

The Sky130 standard-cell library is used as the target technology for the synthesized logic.

The library provides cells that can represent common digital functions, including:

* AND gates
* OR gates
* NAND gates
* NOR gates
* Inverters
* Buffers
* Flip-flops

## Flip-Flop Mapping

Sequential elements are mapped to available Sky130 cells using:

```tcl
dfflibmap -liberty src/lib/sky130_fd_sc_hd__tt_025C_1v80.lib
```

The mapping can be represented as:

```text
RTL Sequential Logic
        ↓
    dfflibmap
        ↓
Sky130 Flip-Flop Cells
```

## Combinational Mapping

The combinational logic is optimized and mapped with ABC:

```tcl
abc -liberty src/lib/sky130_fd_sc_hd__tt_025C_1v80.lib
```

This converts generic combinational logic into cells supported by the selected Sky130 library.

## Handling Undefined Values

Undefined logic values are assigned zero using:

```tcl
setundef -zero
```

This helps produce a deterministic synthesized representation.

## Removing Unused Logic

Unnecessary cells and connections are removed with:

```tcl
clean -purge
```

The cleanup operation can also be performed again after additional synthesis operations.

## Renaming Internal Objects

Yosys-generated objects can be given organized names using:

```tcl
rename -enumerate
```

This produces a more systematic naming scheme in the resulting design.

# 7. Synthesized Netlist

After synthesis and technology mapping, the RTL is converted into a gate-level representation.

Instead of high-level RTL statements, the resulting design consists mainly of technology-specific cells, sequential elements, and their interconnections.

```text
RTL Design
    |
    v
Yosys Synthesis
    |
    v
Optimization
    |
    v
Technology Mapping
    |
    v
Gate-Level Netlist
```

The synthesized design can be written to a Verilog file using:

```tcl
write_verilog -noattr baby_soc_net.v
```

The generated `baby_soc_net.v` file contains the synthesized representation of the design.

# 9. Gate-Level Simulation

The synthesized design is verified again using Gate-Level Simulation (GLS).

In this stage, the synthesized netlist replaces the original RTL implementation. The simulation also requires the Verilog models of the Sky130 standard cells.

The GLS flow is:

```text
Testbench
    +
Synthesized Netlist
    +
Sky130 Verilog Models
    |
    v
Icarus Verilog
    |
    v
Gate-Level Simulation
    |
    v
VCD Waveform
```

The gate-level simulation is compiled with:

```bash
iverilog -DPOST_SYNTH_SIM -DFUNCTIONAL \
-I src/include/ \
-I ../../sky130RTLDesignAndSynthesisWorkshop/my_lib/verilog_model/ \
-I src/module/ \
src/module/testbench.v
```

The resulting executable is run using:

```bash
./a.out
```

The generated waveform can be viewed with:

```bash
gtkwave post_synth_sim.vcd
```

# 10. RTL and GLS Waveform Comparison

After completing both simulations, the generated waveforms are compared.

The two waveform files are:

```text
pre_synth_sim.vcd
post_synth_sim.vcd
```

The important signals considered for comparison are:

* `CLK`
* `reset`
* `RV_TO_DAC[9:0]`
* `OUT`

The comparison process is:

```text
              RTL
               |
               v
       pre_synth_sim.vcd
               |
               | Compare
               |
               v
       post_synth_sim.vcd
               ^
               |
              GLS
```

# 12. Complete Yosys Command Flow

The synthesis commands used for the project are listed below:

```tcl
read_verilog src/module/vsdbabysoc.v
read_verilog -I src/include/ src/module/rvmyth.v
read_verilog -I src/include/ src/module/clk_gate.v

read_liberty -lib src/lib/avsdpll.lib
read_liberty -lib src/lib/avsddac.lib
read_liberty -lib src/lib/sky130_fd_sc_hd__tt_025C_1v80.lib

synth -top vsdbabysoc

dfflibmap -liberty src/lib/sky130_fd_sc_hd__tt_025C_1v80.lib

opt

abc -liberty src/lib/sky130_fd_sc_hd__tt_025C_1v80.lib

setundef -zero

clean -purge

rename -enumerate

stat

write_verilog -noattr baby_soc_net.v
```

### Synthesis Statistics

The `stat` command is used to obtain information about the synthesized design:

```tcl
stat
```

It provides a summary that can include the number and types of cells, wires, and other design information.

# 13. Conclusion

The VSDBabySoC design was taken through the complete RTL-to-gate-level verification process. The RTL was first simulated to establish the expected functionality, after which Yosys was used to synthesize and map the design to the Sky130 standard-cell library.

The resulting gate-level netlist was then simulated using the appropriate standard-cell models. Comparison of the RTL and GLS waveforms for signals such as `RV_TO_DAC[9:0]`, `CLK`, `reset`, and `OUT` showed consistent functional behavior.

Therefore, the synthesis process successfully produced a gate-level implementation while preserving the functionality observed in the original RTL design.
